# 纯净原则实测计划

> 用自己的实测数据说话，不用别人的案例。

## 目标

验证纯净原则在四层框架上的实际效果，用对照实验数据支撑 README 的 before/after 对比。

## 实验设计

**对照组**：同一模型，无 pristine skill，执行标准任务集。
**实验组**：同一模型，加载 pristine skill，执行同一标准任务集。

每组任务跑 3 次取中位数，排除偶然波动。

## 任务集

选 6 个覆盖四层的标准任务：

| # | 任务 | 覆盖层级 |
|---|---|---|
| 1 | 修一个边界 bug（给定有特殊分支的代码） | 思想 + 执行 |
| 2 | 实现一个用户登录功能 | 规划 + 输出（代码） |
| 3 | 回答一个技术问题（给定模糊前提） | 思想 + 输出（对话） |
| 4 | 重构一个有重复代码的模块 | 执行 + 输出（代码） |
| 5 | 解释一个复杂概念 | 输出（对话） |
| 6 | 加一个新功能到已有项目 | 规划 + 执行 |

## 指标

| 指标 | 怎么测 | 对应层级 |
|---|---|---|
| LOC（代码行数） | git diff 统计 | 输出（代码） |
| tokens | API usage 统计 | 全部 |
| cost | 按模型单价计算 | 全部 |
| time | 墙钟时间 | 全部 |
| 前提追溯率 | 回答中是否质疑/确认前提 | 思想 |
| 计划纯度 | 计划中是否包含目标外的伪需求 | 规划 |
| 执行发散率 | 是否做了计划外的事 | 执行 |
| 对话密度 | 废话比例（开场/收尾/跑题） | 输出（对话） |
| 正确率 | 任务是否正确完成 | 全部 |

## 模型

先用一个模型跑通流程，后续扩展多模型对比。
推荐：Claude Haiku（成本低，适合跑多次）。

## 执行步骤

1. 准备任务集的输入 prompt（6 个任务，每个有明确的输入和验收标准）
2. 写一个自动化脚本：依次跑对照组和实验组，收集 metrics
3. 跑数据，生成对比表格和 SVG 图表
4. 更新 README 的 before/after 部分，用真实数据替换"待实测"
5. 把原始数据和图表放在 `benchmarks/results/` 下

## 完成标准

- [ ] 6 个任务的输入 prompt 写好
- [ ] 自动化脚本可运行
- [ ] 对照组和实验组各跑 3 次
- [ ] 生成对比表格
- [ ] 生成 SVG 图表（参考 ponytail 的 benchmark-agentic.svg）
- [ ] README 更新为真实数据

## 成本估算

- 6 任务 × 2 组 × 3 次 = 36 次运行
- 每次运行约 5-20k tokens
- 总计约 200-700k tokens
- Haiku 成本约 $0.5-2
