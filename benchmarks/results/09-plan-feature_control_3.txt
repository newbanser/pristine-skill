我来为你制定一个完整的"导出 CSV"功能实施计划，分为**评估、实施、验收**三个阶段：

---

## 一、需求评估与存量分析（0.5-1天）

| 检查项 | 关键问题 |
|--------|----------|
| **数据源** | 当前报表数据是实时查询还是内存对象？需要统一的导出数据模型吗？ |
| **字符集** | 是否包含中文/特殊符号？需处理 **Excel打开乱码** 问题（加BOM头） |
| **报表类型** | 是明细报表还是汇总报表？导出是否遵循同一套过滤/排序条件？ |
| **后端承载** | 导出时全量加载还是流式生成？**防止大文件内存溢出** 需数据分批写入。 |
| **并发控制** | 是否有权限控制？导出文件是否需要水印或脱敏？ |

---

## 二、技术方案设计（可选2选1）

### 方案A：后端异步导出（推荐）
```
前端点击 → 发起异步请求 → 后端生成CSV文件 → 存临时目录 → 返回下载链接（带过期时间）
```
- **优点**：不阻塞请求，支持大数据量，可加CAS（check-and-set）校验
- **实现要点**：使用 `Commons CSV` 或 `OpenCSV` 流式写入，边查边写

### 方案B：前端纯导出（适用于 <1万行）
```
前端获取当前表格数据 → 组装CSV → Blob下载
```
- **优点**：实现快，不占服务端资源
- **注意**：大数据量卡顿，需处理嵌套对象转花括号

## 三、具体实施任务分解（预计1-2天）

### 第1天：后端接口
```
1. 新增 POST /api/report/export-csv
   - 请求参数：报表ID、筛选条件、排序字段、要导出的列
   - 响应：{downloadUrl, expiresAt}
2. 实现数据查询逻辑（复用原报表查询方法，但仅查必要字段）
3. 增加CSV编码工具类：
   - 字段分隔符：逗号（考虑内容含逗号需用双引号包裹）
   - 表头生成与校验
   - 特殊字符转义
   - UTF-8 BOM 前缀
4. 文件清理定时任务（delete on schedule，比如24h）

### 第2天：前端 + 联调
1. 在按钮`导出`上加 loading 状态 + 禁用重复点击
2. 成功拿到URL后：
   - 创建隐藏 `<a>` 标签触发下载，
   - 或跳转新窗口（需考虑鉴权token放header的场景，改用blob下载）
3. 异常处理：
   - 报错提示"导出失败，请稍后重试"
   - 若超时（如10秒），提示"数据量较大，正在后台生成，稍后通过通知获取"
4. 集成测试用例：
   ```python
   用例1: 空数据导出 → 只含表头
   用例2: 含逗号/引号/换行的字段 → 正确转义
   用例3: 1万行数据 → 性能基准测试
   用例4: 权限校验（无权限用户不能导出）
   ```

## 四、边界情况与防护

| 风险点 | 解决方案 |
|--------|----------|
| **SQL注入** | 导出参数走预编译，白名单校验列名 |
| **数据量过大** | 限制最大行数（如10万行），超过则提示分批导 |
| **并发导出** | 按用户+报表ID加分布式锁，防止频繁生成文件 |
| **文件权限** | 临时文件目录设为不可直接访问，通过URL签名下载 |
| **导出结果与原报表不一致** | 确保SQL不加 `LIMIT`，使用只读事务快照 |

---

## 五、验收标准 Checklist

- [ ] CSV文件能被 Excel/WPS 直接打开不乱码
- [ ] 字段含逗号、引号、换行时，转义正确
- [ ] 中文/英文/数字混合显示正常
- [ ] 大数据量（≥10万行）无内存溢出
- [ ] 无权限用户或错误筛选 → 返回明确错误提示
- [ ] 下载后的新链接不能二次访问（失效控制）
