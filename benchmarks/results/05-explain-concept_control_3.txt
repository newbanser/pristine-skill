**闭包（Closure）** 是 JavaScript 中一个核心且强大的概念。简单来说，**闭包 = 函数 + 该函数所处词法作用域的引用**。

更直白地说：**当一个内部函数引用了外部函数的变量，并且该内部函数被返回（或传递给其他代码）时，即使在外部函数执行完毕后，内部函数仍然可以访问外部函数的变量。** 这个“内部函数”就是闭包。

---

### 核心机制：词法作用域（Lexical Scope）

JavaScript 中的作用域是词法作用域，意味着函数的可访问变量**在定义时**就决定了，而不是在调用时。

---

### 一、最简单的闭包例子

```javascript
function outer() {
  let count = 0;           // 外部函数的局部变量

  function inner() {       // 内部函数（闭包）
    count++;               // 引用外部变量
    console.log(count);
  }

  return inner;            // 返回内部函数
}

const myCounter = outer(); // 执行 outer，返回 inner
myCounter();               // 输出: 1
myCounter();               // 输出: 2
myCounter();               // 输出: 3
```

**发生了什么？**
1. `outer()` 执行完毕后，理论上 `count` 应该被销毁。
2. 但 `inner` 函数返回并保存在 `myCounter` 中，`inner` 的引用链上仍保留着 `count`。
3. 因此 `count` 被“记住”了，每调用一次 `myCounter` 就累加。

### 二、为什么需要闭包？（实际应用）

#### 1. 数据私有化（封装）
闭包可以模拟私有变量，防止外部直接访问和修改。

```javascript
function createBankAccount(initialBalance) {
  let balance = initialBalance;  // 私有变量，外部无法直接访问

  return {
    deposit(amount) {
      if (amount > 0) {
        balance += amount;
        console.log(`存入 ${amount}，余额: ${balance}`);
      }
    },
    withdraw(amount) {
      if (amount > 0 && amount <= balance) {
        balance -= amount;
        console.log(`取出 ${amount}，余额: ${balance}`);
      } else {
        console.log('余额不足或金额无效');
      }
    },
    getBalance() {
      console.log(`当前余额: ${balance}`);
      return balance;
    }
  };
}

const myAccount = createBankAccount(100);
myAccount.deposit(50);    // 存入 50，余额: 150
myAccount.withdraw(30);   // 取出 30，余额: 120
console.log(myAccount.balance); // undefined (无法直接访问)
myAccount.getBalance();   // 当前余额: 120
```

#### 2. 函数柯里化（Currying）
闭包让函数可以“记住”部分参数。

```javascript
function multiplier(factor) {
  return function(num) {
    return num * factor;   // 闭包捕获 factor
  };
}

const double = multiplier(2);
const triple = multiplier(3);

console.log(double(5));    // 10
console.log(double(10));   // 20
console.log(triple(5));    // 15
```

#### 3. 循环中的经典问题（结合 var）

```javascript
// 问题：使用 var 时，所有 i 都是同一个
for (var i = 0; i < 3; i++) {
  setTimeout(function() {
    console.log(i);  // 输出 3, 3, 3 (因为循环结束后 i=3)
  }, 100);
}

// 解决：利用闭包捕获每次的 i
for (var i = 0; i < 3; i++) {
  (function(index) {          // 立即执行函数，创建新作用域
    setTimeout(function() {
      console.log(index);     // 输出 0, 1, 2
    }, 100);
  })(i);
}

// 现代用 let 更简单（let 每次循环创建新的块级作用域）
for (let i = 0; i < 3; i++) {
  setTimeout(function() {
    console.log(i);   // 输出 0, 1, 2
  }, 100);
}
```

### 三、闭包的“陷阱”与注意事项

**1. 内存泄漏**
因为闭包会持有外部函数的变量引用，如果闭包长期存在且引用了大量数据，会导致这些数据无法被垃圾回收。

```javascript
function leaky() {
  const hugeArray = new Array(1000000).fill('data');  // 大数组
  return function() {
    console.log('I hold a large array');  // 引用 hugeArray
  };
}

const leaked = leaky();  // hugeArray 无法被释放，一直占用内存
```

**2. 闭包与循环变量（var）** 已经在上面的例子中演示过。

---

### 四、总结

| 关键点       | 说明 |
|--------------|------|
| **定义**     | 内部函数引用外部函数变量，即使外部函数执行完毕，内部函数仍能访问这些变量 |
| **作用**     | 数据私有化、函数工厂、回调函数、记忆化 |
| **本质**     | 函数 + 词法作用域的引用链 |
| **注意事项** | 可能导致内存占用，需注意释放 |

---

### 一句话比喻
> 闭包就像一个**“背包”**，当内部函数被外出时，它会自动背上外部函数的作用域作为行李，即使外部函数已经“回家”了，背包里的行李依然可用。
