# 纯净原则实测结果

同一个模型（DeepSeek V4-Flash）、同一批任务，对比三组：没装、只要求简洁、装了纯净原则。另外拉了 GitHub 上 star 超 110k 的热门极简 skill 一起比。

## 结论

- 装了纯净原则，输出少 78%（1216 → 271 token）
- 代码全部能跑、全部安全：8 个真实攻击面任务，8/8 零翻车
- 那个 110k star 的热门 skill 压缩更狠（代码行数降到 55%），但有一个任务压缩过头，丢了脏数据容错

## 怎么测的

两类任务，两种测法：

**日常任务（12 个）**：让 AI 直接回答，数输出多少 token，人工抽查质量。每个任务跑 3 次取中位数。任务包括：模糊前提排查、实现登录、写正则、解释报错、重构建议等。

**编码任务（8 个）**：不只是看 AI 写得好不好，而是把代码真的跑起来——用测试用例验证功能对不对，用攻击用例（SQL 注入、路径穿越、签名伪造、DoS）验证有没有漏洞。过了测试才算数。这是最硬的证据。

## 数据

### 日常任务：输出量

| 组 | 平均输出 token | 怎么回事 |
|---|---:|---|
| 没装 | 1216 | 废话、跑偏、自动加戏、撞截断 |
| 只要求简洁 | 136 | 省到不可用，只给方向不给方案，甚至明文存密码 |
| 装了纯净原则 | 271 | 完整但不冗余，该给的全给 |

12 个任务里，纯净原则比没装省 50%~86%，3 次观测一致。

### 编码任务：跑起来验证

8 个任务 × 3 组 × 3 次 = 72 次。代码真的执行，过测试才算达标。

| 组 | 达标 | 翻车 | 平均代码行数 | 平均输出 token |
|---|---:|---|---:|---:|
| 没装 | 8/8 | 0 | 26 | 248 |
| 110k star 热门 skill | 7/8 | csv-sum 丢了脏数据容错 | 15 | 154 |
| 装了纯净原则 | 8/8 | 0 | 19 | 170 |

没装和装了纯净原则都全达标、零翻车，但纯净原则输出更少（比如 todo-null 真实服务器：没装 89 行 / 771 token，装了 65 行 / 547 token，都过 DoS 测试）。那个热门 skill 压缩更狠，但在 csv-sum 上为了短，把空文件和脏数据的容错丢了——3 次里翻了 1 次。

每个任务的原始数据在 `benchmarks/deter/runs/` 目录下。

## 两个例子

**模糊前提。** 用户说"接口返回 500，应该是数据库慢了"。没装的 AI 也质疑了前提，但写了 1545 token，大量铺垫、每步配 SQL 示例；只要求简洁的回了 21 token——"加索引、优化SQL、缓存、分库分表"，一句话术语无法执行；装了纯净原则的写了 226 token，先质疑前提，再给四步可执行的排查路径。

**实现登录。** 没装的 AI 自动加了注册、前端页面、教程，写了 4096 token 撞截断，核心代码没写完；只要求简洁的写了 499 token，代码紧凑但密码明文存储；装了纯净原则的写了 593 token，只做接口，salt + pbkdf2 加盐哈希，预处理防注入。

## 我们没做到的

- 只测了 DeepSeek 一个热门模型，没跨模型验证
- 编码任务是单轮生成，没测"AI 改已有代码"这种多轮场景
- 日常任务的质量是人工抽查，不是全自动判定
- "整个项目省不省"（装了之后少返工、少追问）这件事，我们试了几种测法都不靠谱——让 AI 评审自己的输出它会顺着说，给清单打分又会奖励简洁。这件事暂时没有可信的测法，我们不编数据。能确认的只有：没装的输出返工成本最高（人工抽查达标率 44%，装了的 61%）。

## 怎么复现

```bash
# 编码任务（代码真跑，确定性验证）
python3 benchmarks/deter/skillbench-deter.py --arms empty,pristine,<对比skill的SKILL.md路径> --runs 3

# 日常任务（AI 评审 + 人工抽查）
node benchmarks/skillbench.js
```

## 致谢

这个测试里"把代码真的跑起来验证"这套方法，是从 ponytail 学的。它的确定性 scorer 和自测门禁设计得很干净，我们直接移植了过来。ponytail 在"极致压缩"这条路上走得比我们远，也走得比我们早——向它致敬。

纯净原则走的是另一条路：不追求最短，追求"该给的全给，不该给的没有"。两条路不冲突，各有各的用处。
